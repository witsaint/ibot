# 首页黑云闪电：方案、审查与维护

## 需求与边界

仅增强 SkyClouds 中 `/cloud-3.svg`。保持现有位置、尺寸、层级及静止手绘造型。鼠标进入黑云触发一次随机放电，点击/键盘可再次触发；无自动定时打雷，鼠标一直停留不会循环闪烁。冷白闪电、低饱和蓝色散射匹配黑灰首页。浅色前景云继续遮挡黑云。水池和登录表单不属于本次变更。

参考：用户提供的三张体积云截图与 https://threevfx.com/labs/lightning-strike/#step01 。2026-09-19 读取教程页面及其公开 LightningStrikeStage JS 中的六步说明：随机步进折线、线段 SDF、fBm 边缘抖动、分段消退、辉光和同步点光源。教程是地面落雷，并不包含云体积散射，不能直接用来给 SVG 加真实点光源。

## 实现方案

采用 Three.js 透明局部画布和 GLSL，原 SVG 仍作为静止底图。技术属于 2.5D：根据轮廓、噪声和云团分布构造近似厚度及表面法线，模拟透光，不声称是物理体积渲染或完整 3D 模型。

1. 在内存中栅格化原 SVG。边界连通的透明像素是背景，封闭内部空白并入云体，保留原笔触纹理作为独立信息。不以矩形或几个圆代替原轮廓。
2. 每次触发生成不同的曲折主干和细分支。路径按前后深度分到两张纹理，局部高分辨率绘制细白芯、窄蓝辉光和宽散射，避免全屏后处理。
3. GLSL 通过云轮廓、云团厚度、噪声产生遮挡。后方电弧在厚云处衰减，前方电弧保留细节，形成内外穿行。光源位置随本次路径变化，亮度与放电共用时间包络。
4. 多个局部光源照亮近似云表面，并在薄云和轮廓附近产生较强透光。背景外仅有很弱的晕光，画布四边透明衰减；禁止矩形底和整朵云均匀变亮。
5. 约 1.2 秒一次放电，启动、明亮阶段、细分支消退、余辉结束。峰值限制、触发冷却、减少动态效果偏好降级为单次柔和照明。静止时停止 RAF；失焦/离屏停止；卸载释放纹理、几何体和 WebGL 上下文资源。

## 实施前审查

- SVG 没有 3D 法线，直接添加 PointLight 无效：采用明确的近似厚度/法线模型。若未来要求截图级写实体积，应另行采用体积贴图/光线步进并重新确认美术风格。
- 黑色路径与云轮廓不是同一回事：需要透明区域连通分析，不能只用黑色像素当云体。
- 原云内部线条应仍可辨认：照明层保留笔触调制，亮度不能把云刷成纯白。
- 页面白底会削弱白色辉光：保持白芯，散射使用低饱和冷蓝，云内对比承担主要视觉效果。
- 前景 SVG 有透明空白，CSS z-index 只保证绘制顺序，不会把透明区域变成遮挡面。本次尊重素材原始透明性；不擅自填白邻云。
- 不能使用全屏闪白、镜头摇晃和自动循环；这些参考站效果不适合登录页。
- 图形常量集中在 `cloudLightning.ts`，不扩展全局 UI token；它们是局部着色器美术参数。

## 维护入口与验收

- `StormCloud.tsx`：底图、可访问触发按钮、生命周期。
- `StormCloud.module.css`：画布外扩和按钮样式；位置由 SkyClouds CSS 控制。
- `cloudLightning.ts`：轮廓生成、随机电弧、动画与清理。
- `cloudLightningShader.ts`：厚度、遮挡、照明与透明合成。
- `SkyClouds.tsx`：只将原黑云 Image 替换为 StormCloud。

验收：默认原图；鼠标触发后出现细分支和不同区域照明；不同次路径不同；内外亮度差异可见；结束恢复原图；不循环；点击/键盘可用；减少动态模式不闪烁；WebGL/素材失败仍保留 SVG；桌面与窄屏不出现矩形边缘；全项目 lint/typecheck 与前端 build。

## 调参位置

| 参数               | 入口                                       | 当前值/用途                                                  |
| ------------------ | ------------------------------------------ | ------------------------------------------------------------ |
| 放电时长、触发冷却 | `cloudLightning.ts` 的 DURATION / COOLDOWN | 1250 / 1800 毫秒；不设自动触发定时器                         |
| 电弧纹理分辨率     | WIDTH / HEIGHT                             | 768 × 477；画布实际分辨率随显示大小变化，DPR 上限 1.5        |
| 主干与分支细节     | `bolts()`                                  | 97 个主干点，每 8 点产生一条 9 段分支；每次随机重建          |
| 光源位置           | `bolts()` 返回值                           | 主干的第 25、50、73 点；两个后方光源、一个前方光源           |
| 光色               | `StormCloud.module.css`                    | `--cloud-light-tint`，低饱和冷蓝；白色电弧芯在 shader 中     |
| 云内亮度、笔触保留 | shader 的 bodyAlpha                        | illumination × 2.4，最高 .85，按墨色覆盖率调制               |
| 厚度与表面凹凸     | shader 的 heightAt                         | 固定空间噪声构造近似云团；随机种子只改变照明细节，不移动原图 |
| 后方电弧遮挡       | shader 的 rearVisibility                   | 云体内指数衰减；云体外保留弱电弧                             |
| 外部光晕           | shader 的 spill / haloAlpha                | 三处光源外溢，画布边缘平滑归零                               |

若改变画布外扩比例，必须同时修改 CSS 的 -15% / 130% 和 cloudMask 中的栅格化位置及尺寸；否则光照与原图会错位。更换云 SVG 时也要重新检查封闭轮廓，当前洪水填充对大开口轮廓不能保证正确。

## 实施后自查与验证（2026-09-19）

这是本次实现者的方案和代码自查，不是独立模型审查。

- 初版实际首页尺寸下电弧过于粗折线：增加主干点数，减小单点扰动，细化分支。
- 自定义 shader 的颜色输出需要与 Three.js 色彩空间一致：补上 `colorspace_fragment`，避免照明偏暗。
- WebGL 上下文丢失时不得继续渲染：停止动画并阻止触发，恢复事件后重新允许渲染。
- 浏览器实测：默认保持原 SVG；鼠标进入、点击和 Enter 可触发；多次路径与亮区不同；结束后恢复原图；没有看到矩形画布边缘或着色器错误。
- 测试过减少动态效果模拟：移除电弧纹理，仅保留较弱局部照明。模拟设置已恢复。
- 检查桌面与 768px 窄屏，窄屏可键盘触发；不是完整移动设备兼容性测试。
- `pnpm lint`、全仓库 `pnpm check-types`、`pnpm --filter @i-bot/web build` 均通过。
- 上下文丢失恢复、离屏暂停和卸载清理由代码检查覆盖，本次未通过故障注入逐项实测。

## 效果上限与后续完整 3D 路线

当前成果是手绘云上的局部透光和细电弧，不等同于参考截图的烟雾体积。厚度和法线由程序近似，与原图每一朵云团没有精确的一一对应；前后深度也为艺术控制的两层，并非真实三维电弧。白底和首页较小的云尺寸会使外侧白色辉光较淡。

若后续需要截图级体积感，保留 StormCloud 的触发与布局接口，替换内部渲染器：先为原云制作匹配轮廓的密度体积或多层深度素材，再用光线步进累积密度、透射和散射，让三维电弧采样点提供局部发光。真实体积会增加 GPU 成本，并可能偏离现有手绘风格，应独立验收美术效果与低性能设备降级，不能仅把现有 PlaneGeometry 换为几个球体。

调整参数时先看实际首页尺寸，不能只在放大截图上判断效果。
