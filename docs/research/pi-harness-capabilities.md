源码固定在 main commit [`1b347794e2a630e4359f2584f4eea388145d0ddf`](https://github.com/earendil-works/pi/commit/1b347794e2a630e4359f2584f4eea388145d0ddf)，提交时间为 2026-09-29T22:47:17+02:00。此快照中 coding-agent 与 durable 的 package.json 均标记 `0.99.1`；**没有核实 npm 已发布版本**。以下源码链接固定到此提交，网站的 latest 文档可能继续变化。

## 默认 coding agent 的能力

| 能力                       | 核实结果与边界                                                                                                                                                                                                                                                 | 官方依据                                                                                                                                                                                                                                                                                                                         |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 会话树、分支、fork         | 内置。JSONL entry 带 ID 与 parent；`/tree` 在原文件中改活动分支，`/fork` 从早期用户消息创建新会话，`/clone` 复制活动分支。模型只接收活动分支。会话分支不等于 Git 分支或 worktree，也没有证据证明 fork 会自动合并文件修改。                                     | [Sessions](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/coding-agent/docs/sessions.md)、[Session format](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/coding-agent/docs/session-format.md)                                         |
| 会话恢复                   | 默认保存；`--continue` 恢复当前目录最新会话，`--resume` 选择会话；`--no-session` 不持久化。这里证实的是历史与上下文恢复，不能据此声称崩溃后继续尚未完成的工具副作用。                                                                                          | [Sessions](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/coding-agent/docs/sessions.md)                                                                                                                                                                                            |
| Compaction、branch summary | 内置自动/手动压缩：摘要替代进入模型的旧消息，原始 entry 保留；离开分支可生成摘要供新分支使用。摘要模板包含 Goal，但该字段不是持久目标任务状态机。                                                                                                              | [Compaction](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/coding-agent/docs/compaction.md)                                                                                                                                                                                        |
| Steering、follow-up        | 内置两个队列。steer 在当前 assistant turn 及其工具调用结束后加入；follow-up 在运行准备结束时加入。它不是立即打断一个已启动的点击或进程。SDK 在运行中收到普通 prompt 必须明确指定两种行为之一。                                                                 | [SDK prompting](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/coding-agent/docs/sdk.md#prompting)                                                                                                                                                                                  |
| 运行完成、等待             | `abort()` 停止并等待空闲；`waitForIdle()` 只等待。coding-agent 的 `agent_end` 后可能还有自动重试或排队工作，应使用 `agent_settled` 判断不会自动继续。底层 Agent 的 awaited subscribers 也属于完成等待范围。                                                    | [SDK events](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/coding-agent/docs/sdk.md#subscribing-to-events)、[Agent events](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/agent/README.md#event-types)                                |
| 工具及并发                 | 默认启用 `read/bash/edit/write`。底层 Agent 默认并行执行同一响应的允许调用，preflight 顺序执行，完成事件按实际完成顺序，toolResult 按原调用顺序；任一工具要求 sequential，整批顺序执行。宿主仍须为同一桌面控制、共享状态配置正确顺序。                         | [默认工具](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/coding-agent/src/core/settings-manager.ts#L212)、[执行代码](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/agent/src/agent-loop.ts#L508)                                     |
| Skills                     | 内置 Agent Skills 文件发现：启动时注入名称、描述和路径，完整 SKILL.md 由模型按需读取；`/skill:name` 可强制加载。支持脚本、参考文件和资产。这不是已证实的数据库检索或向量记忆服务。                                                                             | [Skills](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/coding-agent/docs/skills.md)                                                                                                                                                                                                |

## pi-durable 已实装的机制与边界

| 项目                      | 已证实                                                                                                                                                                                       | 仍需宿主实现或未证实                                                                                             |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 存储与崩溃恢复            | SQLite/JSONL；Task 的 pending/running/terminal 状态及 checkpoint；恢复时重新调度未完成任务，stable requestId 避免重复提交。MemoryStorage 不持久化。                                          | 当前一个进程拥有一个 storage，没有跨进程锁，不能推断为现成多 worker 服务。                                       |
| 工具恢复                  | 工具意图先提交；明确 `replay: "safe"` 的中断调用可重跑；其他调用恢复为 interrupted 错误，保留已提交输出。                                                                                    | safe 由工具作者声明；这不保证外部服务的 exactly-once 副作用。                                                    |
| Task 与 Conversation 关系 | TaskOptions 支持 `after` 依赖和 background；Conversation 有 fork 的历史 parent，以及拥有它的 task owner。owned conversation 的前台任务参与祖先空闲等待和取消范围。                           | 不能把 history parent 与 task owner 混为一谈，也不是一个默认业务父子任务产品模型。                               |
| Subagents、等待和取消     | 可在 commit 中创建 task-owned child，等待 child submission；父会话要等前台 owned subtree 空闲；取消 owner 会取消其前台子树。background owner 是边界，不占父空闲等待，不随父普通 abort 取消。 | 注册 `subagent` 工具和具体派工策略仍是宿主/官方示例代码。background 任务结束后如何通知和汇入父上下文需应用实现。 |
| Steering、follow-up       | 持久 inbox；忙时默认 follow-up，可 steer 或 reject；取消 wait 只取消等待，不取消已接收工作。                                                                                                 | 不能把取消等待当作取消任务。                                                                                     |
| HITL、goal、memory        | 有自定义 Document、工具 hooks、memo、任务阶段和继续执行回调，可保存应用状态。`handoff` 是重置模型上下文并附交接说明。                                                                        | 未证实专用持久审批 API、自动用户记忆服务或开箱即用 goal；handoff 不等于浏览器/桌面控制权交接。                   |

上述机制见 [durable README](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/durable/README.md)、[任务与 ownership 类型](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/durable/src/types.ts#L249)、[scheduler 实现](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/durable/src/harness/scheduler.ts)、[ownership 测试](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/durable/test/harness-ownership.test.ts)、[前台示例](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/durable/test/examples/22-subagent-foreground.ts)、[后台示例](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/durable/test/examples/23-subagent-background.ts)。测试在此只作为实装证据，未执行该仓库测试。

## 对 i-bot 评估的直接影响

Pi 可以提供通用模型与工具循环、消息排队、上下文管理和扩展机制；最新 durable 还提供可恢复执行与 owned subtree 等底层机制。是否替换 i-bot 的 harness，应分别评估默认 Agent、AgentSession 和实验性 durable，不宜统一比较。[Agent](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/agent/README.md)、[SDK](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/coding-agent/docs/sdk.md)、[durable](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/packages/durable/README.md)

i-bot 的租户隔离、数据库所有权、沙箱生命周期、桌面人工接管、业务审批、持久目标与通知仍须按自身契约核实和接入。Pi 的 SessionManager 或独立存储若直接成为权威记录，还需评估与本仓库“Drizzle 拥有所有表、内容只有一个存储表示”的约束如何衔接。这是集成推论，未进行实现或运行验证。[本仓库 AGENTS.md](../../AGENTS.md)
