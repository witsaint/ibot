# 网页创作实现

## 入口与范围

可安装插件：`plugins/web-creator`，版本 1.0.5。仅安装、启用该插件的 bot 在最新用户消息以 `/web` 开头时加载流程与专用工具。普通聊天、引用材料和历史提及不会触发。

在 bot 自己的 sandbox 中创建 `/root/projects/<名称>` 前端服务，独立 `design.md` 与源码同目录。右侧展示实际服务预览，支持多个网页与桌面切换。没有网页管理列表或可视化编辑器。

## 流程如何决定

新主题先组织首屏、后续区块、事实与主要操作，再选择设计方向。修改现有网页先读原规范；仅恢复预览只检查服务。没有项目直接初始化；有明确目标沿用对应目录；多个项目且修改目标不明时才询问。

内置六个自行编写的场景方向：阅读、比较、工具、作品、活动、自然。它们提供内容和布局起点，未内置完整主题包。agent 结合内容、受众、素材、手机使用和功能选择最终设计。

## 用户只描述内容

用户不需要提供目录、技术栈、端口或 preview_web 名称。例如：`/web 做一个中文读书笔记网页，有三篇标注为示例的笔记，能按标签筛选并展开阅读，清爽好读。`

新项目由 prepare_web_project 自动创建唯一目录，默认 React + TypeScript + Vite；确需服务端功能时可选内置 Next.js 模板。工具在 bot 的 sandbox 中检查实际监听与其他项目的端口分配，默认从 5173 开始选择空闲应用端口，已有目录拒绝覆盖。模板使用固定依赖版本，写入精确允许的 sandbox host、严格端口与 .ibot-web.json 启动配置，返回安装、构建、后台启动命令。

agent 完成真实内容、设计、安装与启动后，必须主动调用 preview_web。已初始化的项目只传 projectDir 即可读取标题与端口；用户无需了解工具参数。旧项目没有启动配置时由 agent 读取规范与进程，沿用实际端口；多个项目且修改目标无法辨别时才询问网页目标。

## 参考与 design.md

`search_design_styles` 实时读取 StyleKit 公共目录，在服务端匹配关键词，默认仅向模型返回三个候选。`get_design_style` 读取所选风格的颜色、排版、间距、边框、阴影、交互数据；排除完整外部 agent 指令和组件代码。查询仅发往固定公共来源，不附带租户密钥或项目文件。参考不可达时按内置方向自主设计，记录真实状态。

awesome-design-md、Refero、UI UX Pro Max 等保留为按需参考；UI UX Pro Max 搜索程序未安装。资源目录不代表这些服务已接入。

`read_web_project` 检查目录、已有规范、文档版本及当前对话登记的预览。`save_web_design` 要求九个设计章节：视觉主题、颜色角色、排版、组件与状态、布局、深度、规则、响应式与交互、实施提示；另保存真实内容、来源调整、图片、技术和验证状态。新文件使用 null 版本；已有文件需要最近读取到的版本，避免覆盖未读取的修改。结构校验不能代替页面与交互检查。

## 图片与预览

`generate_web_image` 使用服务端 AiProxy GPT Image 2 接口，PNG 写入项目 public/assets。配置 R2 时另存对象副本。密钥不进入模型和 sandbox，工具结果仅保存文件和对象引用。图标默认生成一次，之后复用；失败不阻塞网页预览。

`preview_web` 从当前 sandbox handle 获取域名并检查 HTML 服务，随后登记聊天右侧标签。桌面只显示图标；圆形选中区域采用浅色主题变量。网页优先显示真实图标，无图或加载失败时未选中显示标题首字，选中显示按项目稳定的柔和渐变圆。标题在工具栏与可访问名称中保留。

## 验证与限制

新网页检查手机与桌面、真实主操作、资源和构建；小修改验证受影响部分，预览恢复验证服务。完成后同步项目 design.md，未做检查写明未验证。

当前服务为 sandbox 预览，未接入自动长期托管或整站恢复。没有对象存储时图片也随 sandbox 生命周期保存。当前图像接口已验证 opaque PNG；不声称透明输出已接通。
