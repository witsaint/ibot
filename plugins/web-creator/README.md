# 网页创作插件

i-bot 第一个用于网页创作的可安装插件。包格式由 i-bot 现有插件导入器读取；不是 Codex 桌面插件。

## 主动调用

在聊天输入框的「+ → 插件 → 网页创作」选择入口，再补充需求并发送；或输入：

```
/web 把这些徒步活动资料做成一个手机上好读、可以查看路线的网页
```

用户只需说明主题、内容与想实现的操作。目录、默认技术栈、空闲端口、启动方式和右侧预览由插件处理，无需提到任何工具名称。例如 `/web 做一个中文读书笔记网页，能按标签筛选笔记`。

每次新消息需要此流程时都以 `/web` 开头。普通聊天不注入其 playbook；历史消息、材料中提及 /web 不触发。正在进行的任务里不能通过追加命令更换流程，先停止再调用。仅安装并启用插件的 bot 能使用该命令。

## 安装

使用已登录的插件 API：`POST /api/plugins/install`，请求参数 `dir` 为此包在 API 主机上的绝对路径，`enabledBots` 为指定 bot ID 数组。省略 enabledBots 会应用于该用户的全部 bot。先用 `POST /api/plugins/inspect` 检查导入结果。

无安装脚本、远程 MCP、额外密钥或自动发布步骤。内容保存于平台插件/技能记录，执行时参考文件同步到对应 sandbox；生成项目的 design.md 与代码放在其项目目录。冷桌面安装显示 pending，下一次启动同步。

## 预览

服务启动后，agent 调用 `preview_web`；平台检查服务并取得当前 sandbox 的地址，在聊天右侧打开独立标签。支持切换桌面、多个项目、刷新和在新窗口打开。项目位置和预览引用随工具结果保存在对话中，刷新页面可恢复标签。

## 包内容

一个主动调用入口，九份按需读取的参考文件：流程、内容、六个场景方向、设计、资源、design.md 模板、图像、开发、验收。场景方向是布局与内容起点，没有整库打包 StyleKit 或 UI UX Pro Max。上游参考保留链接与方法摘要。

主动 `/web` 任务提供 search_design_styles 和 get_design_style，从 StyleKit 实时检索少量候选，读取所选风格的设计 tokens。只取设计数据，完整上游 agent 指令和组件代码不注入。不可达时采用内置方向与自主设计，不伪造检索成功。UI UX Pro Max 的搜索程序尚未接入。

read_web_project 检查 sandbox 项目与现有 design.md，save_web_design 按九个设计章节保存最终决定，更新必须使用读取到的文档版本。新主题可直接新建，修改已有网页先读规范；仅预览无需重走内容与设计步骤。完整流程见 skills/web/references/workflow.md。

## 图像

已配置平台 AiProxy key 时，主动 /web 任务可使用 generate_web_image。密钥保留在 API 服务端，PNG 写入项目 public/assets，配置 R2 时保存对象副本。preview_web 的可选 iconPath 使用真实项目图标路径。没有图标/加载失败时未选中显示标题首字，选中显示按项目稳定的柔和渐变圆；桌面标签只显示图标，使用浅色主题背景和圆形边框。
