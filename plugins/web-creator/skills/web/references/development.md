# 在 sandbox 开发与预览

## 初始化

先检查现有项目、Node 与包管理器。全部操作在本 bot 的 sandbox 内进行，不在平台服务器或其他 bot 里执行。新项目优先调用 prepare_web_project，title 为实际主题，不需要用户指定目录。工具自动创建独立项目、写入模板与 .ibot-web.json 启动配置，返回安装、构建与启动命令。不覆盖已有目录。

有项目时沿用其栈与锁文件。无项目时：默认 React + TypeScript + Vite；确需服务端接口、鉴权或 SSR 时选 Next.js + TypeScript。内置模板使用已核对的固定依赖版本，安装后保存锁文件。用户指定其他栈时按实际要求初始化，不为一页静态内容增加数据库或多套组件库。React + Vite 模板需要 Node 20.19+ 或 22.12+；如版本不满足先解决运行环境，不假装服务已启动。

## 开发

- 首屏尽早使用真实内容运行预览，再补全后续区块和交互。
- design.md 的变量在 CSS 中集中定义。生成项目有自己的样式，不默认套用 i-bot 的聊天界面外观。
- 使用语义化 HTML、可访问名称、明确焦点和表单标签。窄屏重排，长中文、无图片和空数据有合理布局。
- 需要图片时使用用户素材或可授权的资源；只有当前可用图像工具存在时才生成图像。不用模糊占位块当完成的视觉资产。
- 主操作应真的执行。尚无报名、支付、联系或存储服务时说明限制，不用 setTimeout 成功提示伪装提交。
- 在包脚本里保存启动与构建命令，运行构建；按平台允许的方式启动后台进程并保存日志，监听 0.0.0.0，避免占用桌面/CDP/VNC 的端口。

## 查看与交付

服务启动后自动调用 `preview_web`。已初始化的新项目仅需 projectDir，平台从 .ibot-web.json 读取标题与端口；有图标时加 iconPath。旧项目未配置时由 agent 从规范、源码与进程取得实际 title 和 port，不能让用户填写技术参数。平台检查 HTML 服务并在聊天右侧打开独立预览标签。工具返回的地址是预览来源，不能猜域名；如果工具报告 Vite host 被阻止，在配置中允许工具返回的精确 hostname 并重启。使用 3000–8999 的应用端口，避开 5900–5999 与 6080 桌面端口。用浏览器打开检查，不能用 localhost 链接声称用户可直接访问。没有平台提供的对外端口 URL 时说明仅能在桌面浏览器预览，不虚构部署能力。

开发服务器用于预览，Vite preview 不是生产托管。只有已具备且用户授权的发布途径才进行公开发布。sandbox 随生命周期结束可能丢失；需要长期网页时检查平台实际提供的托管与备份能力，说明实际保存位置。
