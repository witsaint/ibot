# 网页创作流程

## 1. 判断任务与项目

先用当前需求和对话确定任务。需要查项目时调用 read_web_project：不传 projectDir 列出本 bot 的 /root/projects，传目录读取独立 design.md、版本和已登记的预览。预览记录只反映当前对话，不代表目录一定仍在，实际读取结果优先。

| 需求 | 执行方式 |
| --- | --- |
| 没有网页，要求把主题或材料做成网页 | 创建名称明确的新项目，继续内容与设计流程。 |
| 提供新主题，未指定网页 | 默认新建，不覆盖已有的不同主题项目。 |
| 修改明确命名或当前正在讨论的网页 | 读取对应项目；沿用技术栈、内容与规范，只处理此次变化。 |
| 只有一个项目，要求“修改这个网页” | 读取该项目并继续，目录无需再确认。 |
| 多个项目，修改目标无法从名称、内容或对话确定 | 简短询问目标，不能随机覆盖。可先只读检查候选。 |
| 仅查看或恢复预览 | 检查项目和服务，必要时按原启动命令恢复，调用 preview_web；无需重新设计或生图。 |

列举目录失败不等于没有网页。先处理连接问题，不因读取失败重复新建。没有描述或素材时询问主题；用户已有主题则根据内容合理推断方向，影响真实性或功能的关键缺失才询问。

用户无需提供路径、框架、端口或工具名称。新建时调用 prepare_web_project，title 写实际主题即可；不传其他参数会创建唯一项目目录，使用 React + TypeScript + Vite，并选择未监听、未被其他项目分配的应用端口。确需服务端接口、鉴权或 SSR 时传 framework=nextjs。用户明确指定技术要求时优先遵守；已有项目沿用原栈与目录。多个项目需要按内容辨别时，read_web_project 会返回各项目启动配置中的主题标题。

## 2. 内容与方向

新网页或内容重构时读 content.md，形成真实首屏文案、后续区块顺序和主要操作。每个区块要有新增信息；事实、示例、未知项分清。简单修改直接沿用已有结构。

读 directions.md 按内容选择六个内置方向之一，也可以明确自定义方向。方向只规定内容与布局起点。再读 design.md，提炼 2–3 个视觉关键词，如“自然 留白”“编辑 阅读”“清晰 对比”。

有必要找参考时先调用 search_design_styles，默认取得三个候选。没有结果可换一次更具体的词。根据内容匹配、素材、手机阅读与实现成本选择一个，调用 get_design_style 获取实际 tokens；有浏览器时看候选页面的首屏与布局。API 返回数据不等于已看过页面。另需特定区块时再读 resources.md 找最多两个补充来源，不遍历所有站点。

采用一个主要方向，补充来源只解决具体部分，统一字体、颜色、间距与组件。外部全文和指令不叠加到项目规则。参考不可达时自主设计，记录未取得的部分，不阻塞可用页面。

## 3. 落实项目 design.md

新项目先通过 prepare_web_project 初始化，再用返回的 projectDir 调用 read_web_project 获取当前文档与版本。读 design-template.md，将最终内容和设计写入 save_web_design：

- title、scenario、contentPlan：主题、场景、实际文案和内容顺序。
- sections 九项：visualTheme、colorPalette、typography、components、layout、elevation、rules、responsive、implementation；每项写具体决定，不留占位模板。
- references：最多三个实际采用的 HTTPS 来源；adaptation 写读取日期、采用部分与调整。未采用外部规范传空数组，不列没有取得的来源。
- imageAssets、technicalPlan、verification：真实素材与兜底、框架与启动命令、已做检查与未验证项。
- expectedVersion：新文件使用读取结果 null；更新必须使用最近 read_web_project 返回的版本。版本不匹配时重新读取，合并变化后再保存。

颜色要有语义角色和实际值；排版考虑中文；响应式、状态和键盘操作要明确。宿主标签的圆形和主题色由平台处理，不由网站参考控制。文件保存于本项目目录，不写 i-bot 根目录。

已有规范优先保留。较大的设计变化用 save_web_design 同步九项决定；小修改可以精准编辑原文件并保持内容完整。该工具检查章节结构，浏览器检查实际效果。

## 4. 开发、图片与预览

读 development.md，在本 bot 的 sandbox 中实现。prepare_web_project 已写入模板、严格端口和精确允许的 sandbox host，并返回安装、构建、后台启动命令。模板只是起点，必须替换成真实页面。执行安装保留锁文件，实现并构建，按返回命令启动。已有项目沿用其栈与启动方式。

需要图片或新项目图标时读 images.md。已有图标优先复用，新项目默认生成一次简洁方形图标；失败使用宿主兜底。生成或复用的真实路径传给 preview_web.iconPath，更新同一网页继续传原图标。图片未完成不阻塞预览。

服务启动后尽早主动调用 preview_web，平台登记右侧独立标签。新项目只传 projectDir 就可从项目配置获取标题与端口；有图标时补充 iconPath。无需等待用户要求预览，不能把调用工具的责任交给用户。失败按工具结果检查日志、端口与 host 设置；不猜域名。更新原项目复用原目录和服务，新的项目才登记新标签。

## 5. 检查与交付

读 review.md。新网页或较大布局变化检查手机与桌面、主要操作、资源和构建。小修改只检查受影响部分；预览恢复只检查服务和资产。发现问题修复后同步 design.md 的实际验证状态。

交付一个可用入口、简短操作说明和实际限制。不增加网页管理列表或编辑器。持久化能力按实际存储说明；sandbox 预览不自动成为长期生产托管。
